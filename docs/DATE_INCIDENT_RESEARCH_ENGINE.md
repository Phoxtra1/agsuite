# Date & Incidents — Supabase and Local-First Research

## Runtime architecture

The Date & Incidents page invokes the Supabase Edge Function named `docs-intelligence`. The function receives the `historical_events_search` action with an exact ISO date (including the year), geographical scope and incident category.

The browser uses the existing Supabase client from `src/integrations/supabase/client.ts`; this feature does not route through the Appwrite compatibility adapter. Successful results are cached in account-scoped browser local storage for 24 hours. A fresh local result is returned without making another function request. If a later request fails, the most recent saved result for the same date and filters is used.

Knowledge Compass also keeps recent research matches in account-scoped local storage and combines public research-index results with records from the Supabase-reviewed discovery library.

## Supabase Edge Function

- Function name: `docs-intelligence`
- Source: `supabase/functions/docs-intelligence/index.ts`
- Validation helpers: `supabase/functions/docs-intelligence/historicalEvents.ts`
- Required secret: `GEMINI_API_KEY` (or `GOOGLE_GEMINI_API_KEY`)
- Model: Gemini 2.5 Flash with Google Search grounding
- Request timeout: 55 seconds
- Authentication: Supabase Edge Function JWT verification remains enabled by default.

The Gemini key is read only by the Edge Function. It must never be placed in a browser `VITE_` variable or committed to GitHub.

## Deployment

The Supabase project reference is recorded in `supabase/config.toml`.

1. Add `GEMINI_API_KEY` under the Supabase project's Edge Function secrets.
2. From the repository root, deploy the function with the Supabase CLI:

   ```bash
   supabase functions deploy docs-intelligence
   ```

3. Confirm the deployment is active in Supabase.
4. Test an exact African date and an international date. Confirm the full year is respected, source links come only from Google Search grounding metadata, and unavailable results are not fabricated.

No Appwrite function deployment is required for Date & Incidents.

## Result requirements

- The occurrence date must exactly equal the selected full date, including year.
- Do not substitute a report/publication date, anniversary, or the same month/day in another year.
- Africa is prioritised by default; international events remain in scope.
- Return only prominent, well-documented events; do not pad the list.
- Display source links from Google Search grounding metadata, not arbitrary URLs generated by the model.
- Distinguish corroborated, single-source and contested records, and include date evidence and caveats.

## Local cache behaviour

- Date & Incidents cache: 24 hours, up to 40 date/filter combinations per signed-in/local account.
- Knowledge Compass research cache: 12 hours, up to 30 recent query combinations per signed-in/local account.
- Cache keys are account-scoped using the existing Workspace scope helper.
- If browser storage is unavailable, the search can still run through Supabase, but results cannot be retained locally.
